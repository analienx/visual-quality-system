# Exact Power BI Desktop loaded-source attestation

This optional **G0 evidence guard** supports issue [#16](https://github.com/analienx/visual-quality-system/issues/16). It helps prevent an interaction receipt from being assigned to the wrong open PBIP. It does **not** establish G2 aesthetics, G4 interaction correctness, or independent G6 release approval.

For the October 2026 multi-report Desktop false-dirty investigation, the guarded Windows installer and the exact P1 reacceptance steps, see the [27 October recovery handoff](P1_DESKTOP_RECOVERY_2026-10-27.md).

Run on the authorized Windows host using a **disposable, already-open, saved** PBIP containing exactly one wrapper and its matching report folder. The identity collector supports unrelated report projects; the DAX/UIA runners shown below remain Contoso-specific. Use a unique output file under an ignored/private evidence directory; do not commit raw run receipts, model cache, window captures, or user paths.

```console
python -m scripts.desktop_source_attestation DISPOSABLE_PROJECT --desktop-pid PID --output PRIVATE/desktop-source.json
python -m scripts.contoso_p14_live_oracle DISPOSABLE_CONTOSO_PROJECT --desktop-pid PID --attest-loaded-file --output PRIVATE/dax-oracle.json
python -m scripts.contoso_p16_native_interaction DISPOSABLE_CONTOSO_PROJECT --desktop-pid PID --oracle PRIVATE/dax-oracle.json --attest-loaded-file --output PRIVATE/native-uia.json
```

All three commands are **read-only with respect to report source**; the UIA runner changes supported **in-memory filter selections** and restores the Year state. It never saves or publishes the report. Never use the UIA runner against an open user editing session.

The attestor accepts only all of the following: a real OS `PBIDesktop.exe` with exact PID and exactly one launched PBIP argument matching the discovered physical project; a **single** native Desktop Bridge registry entry matching the expected `.Report` folder and same PID; ready Bridge status; explicit `hasUnsavedChanges: false`; and report files **plus local semantic-model definition files** not modified after that process started. For PBIR `datasetReference.byPath`, the attestor resolves and confines the actual named model, even when its folder name differs from the report; missing, escaped or ambiguous references block. For `byConnection`, the receipt explicitly says the remote model definition was **not** locally verified. **Important separation:** report-level OS/Bridge attestation can still pass for `byConnection` or legacy references, but the strict `--attest-loaded-file` **DAX and UIA paths now additionally require a verified local `byPath` model**. A successful report/window identity must never upgrade an unverified remote semantic model to native data correctness. The standalone receipt includes `model_reference_status` and emits a `model_source_sha256` **only for an explicitly declared, verified `byPath` model**. For legacy or remote references it reports `null`, even if a conveniently same-named `.SemanticModel` directory exists, rather than hashing unrelated files. Desktop-managed `.pbi` / ABF caches are volatile and excluded from source freshness; no refresh or edit is performed. Disagreements block **before** the DAX or UIA action in strict mode. Missing psutil/CLI/registry/permissions also block. Because Desktop may mark a refreshed model unsaved, a legitimate session can remain blocked until its state is resolved safely; do **not** force-save or relax the flag to obtain a green verdict.

The physical source/model digest is still inventoried before and after DAX/UIA. The attestation is evidence of **launch/registered loaded file identity at inspection time**, not cryptographic proof of inaccessible Desktop process memory or that the host was independently reviewed. Independent reviewers must inspect the source-bound private receipts and screenshots; no automating agent should sign its own G6.

The collector **does not contact Bridge at all** if the requested PID's OS command line names an unrelated PBIP. A live negative probe on 26 October 2026 correctly rejected the existing user-protected Desktop process as a different project without interacting with it.

**Desktop 2.159 native-save metadata compatibility (27 October):** The native Save control was observed removing two required authoring `$schema` declarations while satisfying the Desktop saved-state flag. A separate, narrowly allowlisted metadata-only auto-fix exists, but it **does not** authorize bypassing this strict loaded-source attestor. See [P1 reproduction and repair limits](P1_DESKTOP_SAVE_SCHEMA_COMPATIBILITY_2026-10-27.md).

**Acceptance still open:** UIA shapes/country map, interactions on a second unrelated PBIP, authenticated Corporate Spend map, and an independent release reviewer/publisher (consolidated in #16; the implementation issue #80 is closed). The flag is opt-in to preserve the historical limited engineering contract; any new production-release evidence request must enable it and cannot treat a default legacy receipt as attested.
